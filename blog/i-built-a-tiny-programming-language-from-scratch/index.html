I Built A Tiny Programming Language from Scratch

Abdullah Fatota
Updated: 30 September 2026

Backstory

I built Tiny Lang as solution to a coding challenge that asked to implement a non-Turing complete programming language similar in syntax to BrainF---.

However this language has the following constraints:

  • The language must contain a single counter variable which all instructions may manipulate,
  • Each instruction is a length-1 string (character), which makeup the input program.
  • Upon halt the language must return counter value.

I extended the language by adding support for printing, and also built a Playground where you can run Tiny Lang programs and instantly see the results (or wait forever if you wrote an infinite loop 😅)

Syntax reference

Each instruction is a character:

  • + Increments the counter.

  • - Decrements the counter.

  • [ is whileNonZero opening block. Runs the loop body only if the counter is non-zero, else jumps to the closing block.

  • ] is whileNonZero closing block. Jumps back to the opening bock only if the counter is still non-zero.

  • { is ifNonZero opening block. Runs the body only if the counter is non-zero, else jumps to the closing block. It runs the body at most once.

  • } is ifNonZero closing block.

  • > Does nothing. Equivalent to Python pass statement.

  • ! Prints the counter as single ASCII character without new line.

Examples

  • +++ Returns 3

  • +{[-]+}+ Returns 2

  • ++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++!+++++++++++++++++++++++++++++!+++++++!!+++!-------------------------------------------------------------------------------!+++++++++++++++++++++++++++++++++++++++++++++++++++++++!++++++++++++++++++++++++!+++!------!--------!-------------------------------------------------------------------!

    Returns 33 and prints Hello World!

  • +++++++++++++++++++++++++++++++++++++++++++++++++!-!----------------!++++++++++++++++++++++++!------------------------!++++++++++++++++++++++!----------------------!++++++++++++++++++++!--------------------!++++++++++++++++++!------------------!++++++++++++++++!

    Returns 48 and prints the even numbers 10 8 6 4 2 0

Printing

To print Hello World! we print each letter individually by incrementing or decrementing the counter to the ASCII value, and then calling the print command (!), for example:

  • H is ASCII 72, so we increment (+) 72 times.
  • e is ASCII 101, but because the counter is already at 72, we only increment 29 times.
  • and so on...

The first step in running any source code is to tokenize it, or group the individual characters into entities of specific meaning (Tokens).

  • Instruction is a single character (length 1 string),
  • Token is an Object that contains:
    • The instruction type as a TypeScript enum, which makes it easier to build robust and more readable code, and
    • the index of the instruction character.

The index property is extremely useful when building the Jump Table, because I don't have to do O(n) work to find a single instruction's position.

Interpreter architecture

I implemented the interpreter using an immutable or Functional Programming (FP) approach because it makes it easier to reason what the code is doing at a high-level: it makes the execution flow and abstractions clear and explicit and therefore streamlines the solution.

It also leads to more robust code with fewer bugs, because less mutations means less bugs.

So to build a Tiny Lang Interpreter we need to build 4 things:

  1. The interpreter State

    It controls which instruction to read next, and contains the counter value at all times.

  2. The Jump Table.

    It enables the looping and jumping behavior of whileNonZero and ifNonZero, by assisting the Transition Functions to jump backward or forward within the program.

  3. The Transition Functions.

    They are the backbone of the interpreter processing the instructions, they take in the current State, the current instruction, and the Jump Table, and return the new State.

  4. The Main Execution Loop

    This ties everything together, it runs the entire program. It does this by consuming each instruction, calling the appropriate Transition Function, supplying it with the current State, the Jump Table, accepting the newly returned State, and propagating it to the next instruction, and so on.

State

TypeScript
1type State = {
2    readHead: number;
3    counter: number;
4};
5
6let currentState: State = {
7    readHead: 0,
8    counter: 0,
9};

Pursuing FP, I modelled the State as an immutable object with two entries:

  1. the counter, and
  2. the read head, as it enables the looping and jumping behavior of whileNonZero and ifNonZero because it decides which instruction to read (past or next).

A State object is never mutated, we simply obtain a new copy after processing each instruction.

The Jump Table

TypeScript
1//...
2
3/*
4    Record locations of WhileStart, WhileEnd, IfStart, IfEnd
5    we don't need IfEnd -> IfStart because once if reaches end it cannot loop back
6*/
7type JumpTable = Map<number, Token>;
8
9// ...
10
11const buildJumpTable = (tokens: Token[]): JumpTable => {
12    // match [] {} used to build jump tables
13    const stack: Token[] = [];
14
15    const jumpTable: JumpTable = new Map();
16
17    for (const token of tokens) {
18        const { type, index } = token;
19        if (type === TokenType.WhileStart || type === TokenType.IfStart) {
20            stack.push(token);
21        }
22        // do it both ways, jump[start] = end, and jump[end]=start
23        else if (type === TokenType.WhileEnd) {
24            const loopStart = stack.pop();
25
26            if (loopStart === undefined) {
27                raiseMalformedInput();
28            }
29
30            // malformed input
31            if (loopStart.type !== TokenType.WhileStart) {
32                raiseMalformedInput();
33            }
34
35            // in case we need to skip over the loop; jump[start] = end
36            jumpTable.set(loopStart.index, token);
37
38            // in case we need to loop back; jump[end] = start
39            jumpTable.set(index, loopStart);
40        }
41        // only one way jump[ifStart] = ifEnd; because we cannot go back/loop
42        else if (type === TokenType.IfEnd) {
43            const ifStart = stack.pop();
44
45            if (ifStart === undefined) {
46                raiseMalformedInput();
47            }
48
49            // malformed input
50            if (ifStart.type !== TokenType.IfStart) {
51                raiseMalformedInput();
52            }
53
54            jumpTable.set(ifStart.index, token);
55        }
56    }
57
58    // malformed input, incomplete closing token e.g. "[+"
59    if (stack.length > 0) {
60        raiseMalformedInput();
61    }
62
63    return jumpTable;
64};

We use two data structures to build the Jump Table:

  1. A Stack and a standard pair-matching algorithm to find all the opening and closing block tokens,

  2. A Hash Map to store their index locations.

Continuing with ++{[-]+}+ as example, we first iterate over all the tokens:

  • If the token is an opening block ([ or {) we push them onto the stack for later inspection.

  • If the token is a closing block (], }), we pop the stack and that's where the real work starts:

If the popped token is mismatched (e.g. program is {]), we raise an exception by calling raiseMalformedInput which is usufuel both to the Terminal and Playground GUI to show a Syntax Error badge.

If the popped token matches the opening block, we store the character/token indicies in our Hash Map Jump Table, For whileNonZero we need to store both indicies:

Plain Text
1WhileStart -> WhileEnd
2WhileEnd -> WhileStart

This because we might need to skip the body, or loop again depending on the counter value at runtime.

For ifNonZero though we store it only one-way:

Plain Text
1IfStart -> WhileEnd

This because ifNonZero cannot loop back, the body runs either zero or one times.

Transition Functions

TypeScript
1// produce our next state
2type StateFunction = (state: State, globalJumpTable: JumpTable) => State;
3
4const tokenTypeToTransitionFunction: Record<TokenType, StateFunction> = {
5    [TokenType.Print]: processPrint,
6    [TokenType.Pass]: processPass,
7    [TokenType.Increment]: processIncrement,
8    [TokenType.Decrement]: processDecrement,
9    [TokenType.WhileStart]: processWhileStart,
10    [TokenType.WhileEnd]: processWhileEnd,
11    [TokenType.IfStart]: processIfStart,
12    [TokenType.IfEnd]: processIfEnd,
13};

For each Token we construct a handler function that always takes in:

  1. the current Token and,
  2. a reference to the global Jump Table

Each Transition Function returns a new State, and possibly does a side-effect like printing (like the print instruction !).

To give a concrete example, we'll take a look at processing 3 types of Instructions:

  • + Increment
  • [ as whileNonZero loop opening, and
  • ] as whileNonZero closing instruction

Processing +

TypeScript
1// process "+" increment instruction
2// increment current counter, move to next instruction.
3const processIncrement = (currentState: State): State => {
4    const { counter, readHead } = currentState;
5    return {
6        counter: counter + 1,
7        readHead: readHead + 1,
8    };
9};

We extract the current counter, and read head from the provided State, and simply increment both the counter, and the read head to the next instruction.

Processing [

TypeScript
1// process "[" while start instruction
2// if counter is 0, jump to end of loop, otherwise advance read head and enter "body"
3const processWhileStart = (
4    currentState: State,
5    passedJumpTable: JumpTable,
6): State => {
7    const { counter, readHead } = currentState;
8
9    // jump to end of loop
10    if (counter === 0) {
11        // malformed input
12        if (!passedJumpTable.has(readHead)) {
13            raiseMalformedInput();
14        }
15
16        const WhileEnd = passedJumpTable.get(readHead);
17        const nextIndex = WhileEnd.index;
18
19        return { counter, readHead: nextIndex };
20    }
21
22    // else enter the loop, move to next instruction
23    return { counter, readHead: readHead + 1 };
24};

This is the opening block of the whileNonZero loop. So we extract the current counter, and read head from the provided State, and make a decision:

  • If the counter is not 0, we enter the loop body by simply incrementing the read head.

  • If the counter is 0, we skip the entire loop body, and jump to the closing block ].

    We do that by by getting the index of the closing block ] from the Jump Table, and setting the read head to that.

Processing ]

TypeScript
1// process "]" while end instruction
2// if counter is not 0, loop back, jump to "[" beginning
3const processWhileEnd = (
4    currentState: State,
5    passedJumpTable: JumpTable,
6): State => {
7    const { counter, readHead } = currentState;
8
9    // loop back, jump to loop start
10    if (counter !== 0) {
11        if (!passedJumpTable.has(readHead)) {
12            raiseMalformedInput();
13        }
14
15        const loopStart: Token = passedJumpTable.get(readHead);
16        const startIndex = loopStart.index;
17
18        return { counter, readHead: startIndex };
19    }
20
21    // counter === 0; move to next instruction
22    return { counter, readHead: readHead + 1 };
23};

This the closing block of whileNonZero so we have to decide if we're done looping, or run the body again:

  • If the counter is 0, we exit the loop body by simply incrementing the read head.

  • If the counter is not 0, we loop by jumping back to the opening block [.

    We do that by getting the index of the opening block [ from the Jump Table and setting the read head to that.

Processing !

We convert the numerical representation of the counter to ASCII, we call process.stdout.write if the interpreter runs in Node.js or printFunction supplied by the user.

Finally we advance the read head.

TypeScript
1// process "!" print instruction
2// side effect: print the single counter as ascii. advance read head.
3const processPrint = (currentState: State, _passedJumpTable): State => {
4    const { readHead, counter } = currentState;
5
6    // without new line
7    const character = String.fromCharCode(counter);
8
9    // external custom accumulating/printing function
10    if (printFunction) {
11        printFunction(character);
12    }
13
14    // otherwise default in Node.js
15    else if (typeof process !== "undefined") {
16        process.stdout.write(character);
17    }
18
19    return { counter, readHead: readHead + 1 };
20};

Processing >

We do nothing but advance the read head. The instruction is equivalent to the pass statement in Python.

TypeScript
1// process ">" pass instruction
2// just advance read head, move to next instruction. we don't need the jump table
3const processPass = (): State => {
4    const { readHead, counter } = currentState;
5
6    return { counter, readHead: readHead + 1 };
7};

Processing -

We simply decrement the counter, and advance the read head.

TypeScript
1// process "-" decrement instruction
2// decrement current counter, move to next instruction.
3const processDecrement = (
4    currentState: State,
5    _passedJumpTable: JumpTable,
6): State => {
7    const { counter, readHead } = currentState;
8    return {
9        counter: counter - 1,
10        readHead: readHead + 1,
11    };
12};

Processing {

  • If the counter is 0, we skip the body, and jump to the closing block }. We do that by consulting the passed global Jump Table and setting the read head to the matching } location..

  • If the counter is not 0, we enter the condition body by simply advancing the read head.

TypeScript
1// process "{" if start instruction
2// if counter is 0, jump to end of condition, otherwise advance read head and enter "body"
3const processIfStart = (
4    currentState: State,
5    passedJumpTable: JumpTable,
6): State => {
7    const { counter, readHead } = currentState;
8
9    // jump to if end
10    if (counter === 0) {
11        // malformed input
12        if (!passedJumpTable.has(readHead)) {
13            raiseMalformedInput();
14        }
15
16        const ifEnd = passedJumpTable.get(readHead);
17        const jumpIndex = ifEnd.index;
18
19        return { counter, readHead: jumpIndex };
20    }
21
22    // else enter if
23    return { counter, readHead: readHead + 1 };
24};

Processing }

Since there is no looping back from the end of ifNonZero to the beginning, we simply advance the read head.

TypeScript
1// process "}" if end instruction
2// "if" cannot loop back, so just advance read head
3const processIfEnd = (
4    currentState: State,
5    _passedJumpTable: JumpTable,
6): State => {
7    const { counter, readHead } = currentState;
8
9    return { counter, readHead: readHead + 1 };
10};

Main Execution Loop

TypeScript
1const processToken = (
2    currentToken: Token,
3    globalJumpTable: JumpTable,
4): State => {
5    const { type, _index } = currentToken;
6
7    // invalid character
8    if (type === undefined) {
9        raiseMalformedInput();
10    }
11
12    const transitionFunction = tokenTypeToTransitionFunction[type];
13    const nextState = transitionFunction(currentState, globalJumpTable);
14
15    return nextState;
16};
17
18// run the program the program, as long as there are instructions
19while (currentState.readHead < tokens.length) {
20    const currentToken = tokens[currentState.readHead];
21    const nextState = processToken(currentToken, globalJumpTable);
22    currentState = nextState;
23}

The while loop is our conductor, it runs the entire supplied program (as string), for each instruction:

  • It calls the appropriate Transition Function, and provides it with the:

    • current State
    • current Token
    • the Jump Table

  • It then updates the global reference (currentState) to point to the newly returned State.

  • and repeats the process for the next instruction.

Time Complexity

Our entire solution, both interpreter construction and running the input program has time complexity:

O(n) + O(T) or O(n + T)

  • n is the input string length, or equivalently program size or tokens count.
  • T is the number of instructions encoded in the program itself.

O(n) is the work done building the interpreter including the Jump Table, and it's proportional to the count of tokens that make up the static program.

O(T) is the work done by the interpreter which reflects the behavior of the encoded program itself.

If the program encodes a linear algorithm, our interpreter will run in linear time. If the encoded algorithm is exponential our interpreter will take exponential time to complete. If the program encodes an infinite loop, our interpreter will never halt.

In short the Time Complexity is work done by processing the input in addition to the growth behavior of the encoded program itself.

Space Complexity

Our entire solution, both interpreter construction and running the input program has space complexity:

O(n)

With n being the input string length, or tokens count.

Or equivalently work proportional to the program size.

Conclusion

I implemented a tiny programming language similar to BrainF---, while it cannot program any arbitrary (Turing) program because that requires at least 2 counters, nonetheless it can print Hello World! just using a single variable!
