Backstory

I wanted an easier and sustainable way to embed SVG icons in my GitHub page (this one), and most important make their css: fill or css: stroke match whatever the inherited or set css css: color property was.

The browser is doing all the heavylifting here because the trick is to set html: fill=currentColor on the DOM element when the svg element was loaded.

This can be done manually by editing the SVG file and adding the attribute name value directly, however that does not scale for multiple files, is cumbersome and error prone, so enjoy this component.

3/*
4*   <SVG/> React Component
5*   Version: 1.3
6*   Author: Abdullah Fatota
7*   License: MIT
8
9*   ## Limitations
10
11    Due to the async nature of reading the SVG files during runtime, there is a noticeable lag between when the time the browser first loads the page and the subsequent separate loading (and coloring) of the SVG file.
12
13*   Usage example:
14        <SVG path="/sun-solid.svg" />
15
16*   Mandatory Props:
17        "path": (string) path to the svg file to be loaded
18
19*   Optional Props:
20        "set-fill": (boolean) by default set to `true`; sets fill="currentColor" attribute value pair on the DOM svg element
21        "set-stroke": (boolean) by default set to `false`;  sets stroke="currentColor" attribute value pair on the DOM svg element
22*/
23
24import { useState, useEffect } from "react";
25
26export const SVG = ({
27    path,
28    className,
29    style,
30    "set-fill": setFill,
31    "set-stroke": setStroke,
32}) => {
33    /*
34        returns an object from DOM element's attributes e.g. {xmlns: "http://www.w3.org/2000/svg" viewBox: "0 0 512 512"} 
35        from the element e.g. <svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 512 512"> 
36    */
37    const getAttributes = (element) =>
38        [...element.attributes].reduce((obj, { name: originalName, value }) => {
39            const name = originalName === "class" ? "className" : originalName;
40            obj[name] = value;
41            return obj;
42        }, {});
43
44    const [state, setSVG] = useState({
45        loaded: false,
46        svgElement: undefined,
47    });
48
49    const readSVGFile = async () => {
50        try {
51            const promise = await fetch(path);
52            const xml = await promise.text();
53            return { completed: true, xml };
54        } catch (error) {
55            /* icon `path` is most probably invalid */
56            console.error(error);
57            return { completed: false };
58        }
59    };
60
61    const parseSVG = async () => {
62        const response = await readSVGFile();
63
64        if (response.completed === false) return;
65
66        const { xml } = response;
67
68        const svgElement = new DOMParser()
69            .parseFromString(xml, "image/svg+xml")
70            .querySelector("svg");
71
72        if (setFill !== false) svgElement.setAttribute("fill", "currentColor");
73        if (setStroke === true)
74            svgElement.setAttribute("stroke", "currentColor");
75
76        setSVG((prevState) => ({
77            ...prevState,
78            loaded: true,
79            svgElement,
80        }));
81    };
82
83    useEffect(() => {
84        parseSVG();
85    }, []);
86
87    return (
88        <svg
89            style={style}
90            className={className}
91            {...(state.loaded
92                ? {
93                      ...getAttributes(state.svgElement),
94                      dangerouslySetInnerHTML: {
95                          __html: state.svgElement.innerHTML,
96                      },
97                  }
98                : {})}
99        ></svg>
100    );
101};

Task

Create a React component to dynamically load any SVG file, and make it match current css: color property (of the parent HTML element).

Crux of The Solution

The Browser with css: currentColor is doing all the heavy-lifting, so whenever the css: color property of the current or parent element changes, html: <svg></svg> element is colored automatically.

Specifically jsx: <SVG/> will do the following:

  1. Read any file-extension: .svg file during run-time.

  2. Parse it into an html: <svg></svg> element.

  3. Add the html: fill = "currentColor" attribute.

All of this in React.

Usage

React
1<SVG path="/sun-solid.svg" />

Prop jsx: path provided by the user points to the file-extension: .svg file to be loaded, and colored accordingly.

High-level Overview

The js: fetch() Web API because the component must be able to read any file-extension: .svg file, it is asynchronous therefore js: await

jsx: useEffect() because we need to run async code inside React.

js: new DOMParser() because we need an actual html: <svg></svg> DOM element, not just the string of text returned by js: fetch . We also use js: .querySelector("svg") because the parser returns a full document that contains the html: <svg></svg> element.

jsx: setLoaded because we need to render the html: <svg></svg> element from inside jsx: useEffect() and this is the only way to do it in a functional component. Once jsx: setLoaded changes jsx: loaded to jsx: true then the code inside jsx: return runs.

jsx: dangerouslySetInnerHTML because that is the only way, that I know of, to make React render the live svg DOM element we have.

jsx: ...[...svg.attributes].reduce because there is no way to make React only render the svg element itself through jsx: dangerouslySetInnerHTML without wrapping in another element. Therefore we jsx: innerHTML and copy all the attributes from the original svg element.
