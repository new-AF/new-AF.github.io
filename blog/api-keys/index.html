API Keys

Abdullah Fatota
Updated: 12-9-2025

Objectives

We'll implement more functions to run between the Request and Response journey:

  • Basic but weak authorization middleware to ensure only applications with a valid API Key can access our API.

  • Server-side Logging to ensure each request is logged, both for debugging purposes and foundation for production purposes.

Our middleware pipeline will be:

Logging -> JSON parsing -> Authorization -> Router -> Error Handling

  1. Logging (logRequest in src/middleware/logRequest.ts)

  2. JSON parsing of Request body (provided by Express)

  3. Authorization (checkApiKey in src/middleware/checkApiKey.ts)

  4. Our Router mapping endpoint to controllers (userRouter in src/routes/user.route.ts)

  5. Error handling passed from controllers ( errorHandler in src/middleware/errorHandler.ts)

Create Logging Middleware

The Date format will be the widely-used DD/MM/YYYY HH:mm:ss.SSS

src/middleware/logRequest.ts
import { Request, Response, NextFunction } from "express";

const getTimeWithDateUTC = (): string => {
    const time = new Date().toLocaleString("en-GB", {
        year: "numeric",
        month: "2-digit",
        day: "2-digit",
        hour: "2-digit",
        minute: "2-digit",
        second: "2-digit",
        fractionalSecondDigits: 3,
        hour12: false,
        // Force UTC for global consistency
        timeZone: "UTC",
    });

    return `${time} UTC`;
};

export const logRequest = (
    request: Request,
    _response: Response,
    next: NextFunction
) => {
    const time = getTimeWithDateUTC();
    const { method, originalUrl } = request;
    console.log(`[${time}] ${method} ${originalUrl}`);

    // Authorization middleware: check API key
    next();
};

Create Authorization Middleware

Authorization means checking if the requester is allowed to access our API.

One basic but weak way of doing that is by using API Keys, by having the requester repeat back/provide us the API Key we shared with them beforehand.

API Keys

An API Key is essentially is a code word that we provide to approved applications, so when they call our API and send us the same API Key, we know they're good to receive back information and services.

As an HTTP Request is made of two parts:

  1. HTTP Header (metadata about the request, made of key-value pairs)

  2. HTTP Body/Payload

API Keys are almost always sent in the header because:

  • not all requests have a body (e.g. GET and DELETE)

  • semantically it matches, the header includes information that helps the server understand how to process the request, and is not the actual data/body.

Warning

API Keys are useful for tutorials or limited systems, but they are weak security for real-word production systems because whoever has the key regardless of how they obtained it, can have full access to the backend.

  • They can be leaked via logs, GitHub commits, etc.

  • They can be intercepted if connection is not HTTPS

  • They only identify the request, not the user themselves.

  • Depending on the backend, they may rarely expire and could be hard to rotate or revoke individually.

Later we'll use a stronger security framework (OAuth 2.0) but for now this is sufficient.

src/middleware/checkApiKey.ts
import { Request, Response, NextFunction } from "express";
import { API_KEY } from "@/config/environment";

export const checkApiKey = (
    request: Request,
    response: Response,
    next: NextFunction
) => {
    const providedKey = request.headers["x-api-key"];

    if (providedKey === undefined) {
        response.status(401);
        response.json({
            message: "Unauthorized request: Missing API Key",
        });
        return;
    }

    if (providedKey !== API_KEY) {
        // Unauthorized
        response.status(401);
        response.json({
            message: "Unauthorized request: Invalid API Key",
        });
        return;
    }

    // Controllers
    next();
};

Generate Key

An API Key should be a cryptographic string (long uniformly-random alphanumeric characters) where each next character cannot be predicted or guessed and therefore is infeasible to brute-forcing so keys like my-dev-key can be compromised instantly.

Wire The Middlewares

Update Server Entry Point.

src/server.ts
import express from "express";
import { PORT } from "@/config/environment";
import { userRouter } from "@/routes/user.route";
import { logRequest } from "./middleware/logRequest";
import { checkApiKey } from "./middleware/checkApiKey";
import { errorHandler } from "./middleware/errorHandler";

const app = express();

// --- Middleware ----
// 1) Log every request
app.use(logRequest);

// 2) Convert request body to JSON
app.use(express.json());

// 3) Authorization
app.use(checkApiKey);

// 4) Controllers
app.use("/api/v1/users", userRouter);

// 5) Handle Errors
app.use(errorHandler);

app.listen(PORT, () => {
    console.log(
        `🚀 Day 6: API Keys server running on http://localhost:${PORT}`
    );
});
