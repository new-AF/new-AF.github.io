Schema Overview

Schema is the data format and constraints that we want our data to follow. For the entire project we have 3 schemas so far:

  1. Server-side or Internal database users, let's call it userModelSchema because it is the 'main' user data shape that we use for our database.

    Unknown Code
    1{
2    id: (integer >= 1);
3    name: (valid name as discussed);
4    email: (valid email address);
5}

  2. Client-provided payload with POST, or createUserSchema

    Unknown Code
    1{
2    name: (valid name as discussed);
3    email: (valid email address);
4}

  3. The GET user by id query parameter, or userIdParamsSchema

    Unknown Code
    1{
2    id: (integer >= 1)
3}

name must be of length 1 or more of alphabetic characters (with optional space between them) and we will re-use the same regex for validation like we discussed in Day 3.

Schema Definitions

We're replacing user.validator.ts with a new file user.schema.ts to precisely enforce the types we want:

  • userModelSchema is the runtime validator that will use after we create a new user but before we insert it into the database, to ensure its contents follow the schema we defined. UserModel is the derived static TypeScript type.

  • createUserSchema for POST runtime validation, and derived CreateUserBody static type.

  • userIdParamsSchema for GET by id runtime validation, and derived UserIdParams static type.

TypeScript
1/* fileName: src/validators/user.schema.ts */
2import { z } from "zod";
3
4// Regex to match alphabetic characters (upper/lowercase) and optional space between
5const namePattern = new RegExp(
6    [
7        // Start of string
8        "^",
9
10        // First word (letters only)
11        "[A-Za-z]+",
12
13        // Start group for "space + word"
14        "(",
15
16        // Space
17        "\\s",
18
19        // At least one letter
20        "[A-Za-z]+",
21
22        // Repeat zero or more times
23        ")*",
24
25        // End of string
26        "$",
27    ].join(""),
28    "u"
29);
30
31// Full user model schema (server-side shape)
32export const userModelSchema = z.object({
33    id: z.number().int().min(1, "ID must be 1 or higher"),
34
35    name: z
36        .string()
37        .min(1, "Name is required")
38        .regex(namePattern, "Name must contain only letters and spaces"),
39
40    email: z.email("Invalid email address").min(1, "Email is required"),
41});
42
43export type UserModel = z.infer<typeof userModelSchema>;
44
45// Schema for POST /users body without `id`
46export const createUserSchema = userModelSchema.omit({ id: true });
47export type CreateUserBody = z.infer<typeof createUserSchema>;
48
49// Schema for validating `/users/:id` route params
50export const userIdParamsSchema = z.object({
51    id: z.coerce.number().int().min(1, "ID must be 1 or higher"),
52});
53export type UserIdParams = z.infer<typeof userIdParamsSchema>;

Modify the Controller

To validate that incoming data (and new users that we create) match the schemas we defined.

TypeScript
1/* fileName: src/controllers/user.controller.ts */
2import { Request, Response } from "express";
3import {
4    createUserSchema,
5    userIdParamsSchema,
6    userModelSchema,
7    type UserModel,
8} from "@/validators/user.schema";
9
10import { z } from "zod";
11
12const users: UserModel[] = [
13    { id: 1, name: "Alice", email: "alice@example.com" },
14    { id: 2, name: "Bob", email: "bob@example.com" },
15];
16
17// POST /users
18export const createUser = (request: Request, response: Response) => {
19    // Request body already parsed as JSON
20    const requestBody = request.body;
21
22    const bodyResult = createUserSchema.safeParse(request.body);
23    const { success, data, error } = bodyResult;
24
25    if (success === false) {
26        // Bad request, often malformed user input
27        response.status(400);
28        response.json({
29            error: z.flattenError(error),
30        });
31        return;
32    }
33
34    const { name, email } = data;
35    const newUser: UserModel = { id: users.length + 1, name, email };
36
37    // Validate final model shape as a guard-rail
38    const modelCheck = userModelSchema.safeParse(newUser);
39    if (modelCheck.success === false) {
40        response.status(500);
41        response.json({ error: "Internal model validation failed." });
42        return;
43    }
44
45    users.push(newUser);
46
47    // Resource created
48    response.status(201);
49    response.json(newUser);
50};
51
52// GET /users
53export const getAllUsers = (_request: Request, response: Response) => {
54    response.status(200);
55    response.json(users);
56};
57
58const searchUsers = (userId: Number) => {
59    // Search users 'database', returns first matching object, or `undefined` if none are found
60    const result = users.find((user) => userId === user.id);
61
62    if (result === undefined) return { success: false };
63
64    return { success: true, user: result };
65};
66
67// GET /users/:id
68export const getUserById = (request: Request, response: Response) => {
69    const {
70        success: paramParseSuccess,
71        data,
72        error,
73    } = userIdParamsSchema.safeParse(request.params);
74
75    if (paramParseSuccess === false) {
76        response.status(400);
77        response.json({ error: z.flattenError(error) });
78        return;
79    }
80
81    const { id: userId } = data;
82
83    const { success, user } = searchUsers(userId);
84    if (!success) {
85        response.status(404);
86        response.json({
87            error: `User with id ${userId} not found`,
88        });
89        return;
90    }
91
92    response.status(200);
93    response.json(user);
94};
