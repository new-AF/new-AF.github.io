Overview

I asked an AI to be my mentor and plan a 30-day backend API development using Node.js with the best DX (developer experience), this means using modern best practices and working with TypeScript for type safety.

The stack so far is:

  • TypeScript

  • Express

  • Node

  • Zod for runtime validation, that TypeScript isn't able to verify (incoming HTTP Payloads)

Testing will be done with:

  • built-in Node test runner

Disclaimer: While the AI was happy to output lots of code, I structured the project journey and modified the code as I saw fit. I also documented the process in my own words in the form of these articles. So let's do this.

Project Structure

The 30 day project is structured as a single Git repository with package dependencies installed once at the root, but separate Day X folders with separate source files. Example:

  • 30-days-of-node-api-dev/

    • day-1-setup

    • day-2-routing

    • ...

A bit detailed view:

Note: You don't need to recreate the tree below, it is just a birds-eye overview how the Day X mini-projects should look like.

30-days-of-node-api-dev/
│
├── package.json                      # Shared dependencies and scripts
├── pnpm-lock.yaml
├── tsconfig.json                     # Shared TS config
├── .gitignore
│
├── day-1-setup/
│   ├── tsconfig.json                 # Local TS config, @ alias to src/*
│   ├── .env                          # Environment variables
│   └── src/
│       ├── server.ts                 # Express server entry point
│       └── config/
│           └── environment.ts        # exports ENV variables (from .env and internal)
│
└── day-2-routing/
    ├── tsconfig.json
    ├── .env
    └── src/
        ├── server.ts
        ├── config/
        │   └── environment.ts
        ├── controllers/
        │   └── user.controller.ts
        └── routes/
            └── user.routes.ts

1/9 Install Programs

  • Git (includes Bash Terminal for Windows)

  • Node.js

  • pnpm package manager

  • HTTPie (for testing API endpoints)

2/9 Initialize Git

Bash
git init

  • Create .gitignore to ignore node_modules

.gitignore
node_modules

3/9 Setup Project

Bash
pnpm init

  • Modify package.json to:

    • Add json: scripts: {...} run commands

    • Delete (or modify) "license": "ISC" (permissive open source) to your liking.

package.json
{
    "name": "30-days-of-node-api-dev",
    "version": "1.0.0",
    "description": "",
    "main": "index.js",
    "scripts": {
        "day-1": "tsx watch --tsconfig day-1-setup/tsconfig.json day-1-setup/src/server.ts"
    },
    "keywords": [],
    "author": ""
}

4/9 Install Packages

Bash
pnpm add express dotenv -D typescript @types/node @types/express tsx

Why we need these:

  • express is the backend framework

  • typescript TS compiler

  • @types/node@types/express Type definitions for the TS Compiler to ensure our code passes all static type checks. VSCode also uses them for type hints and autocomplete.

  • tsx to restart our .ts server when file changes.

  • dotenv for managing environment variables incl. secrets

5/9 Config Files

Root tsconfig.json

  • Create the shared tsconfig.json for TS compiler.

tsconfig.json
{
    "compilerOptions": {
        "target": "ES2022",
        "module": "ESNext",
        "moduleResolution": "Node",
        "esModuleInterop": true,
        "skipLibCheck": true,
        "baseUrl": ".",
        "paths": {
            "@/*": ["src/*"]
        }
    },
    "exclude": ["node_modules"]
}

Local .env

  • Create Folder day-1-setup

  • Create day-1-setup/.env for raw environment variables e.g. PORT and API Keys.

day-1-setup/.env
PORT=3000

Local tsconfig.json

  • Create local day-1-setup/tsconfig.json to enable better DX @-style imports, @ becomes an alias for src

day-1-setup/tsconfig.json
{
    "extends": "../tsconfig.json",
    "compilerOptions": {
        "baseUrl": "src",
        "paths": {
            "@/*": ["*"]
        }
    },
    "include": ["src"]
}

Local environment.ts

  • Create day-1-setup/src/config/environment.ts for finer processing env variables.

day-1-setup/src/config/environment.ts
import dotenv from "dotenv";
import path from "path";

// Load the .env from the current day's folder
dotenv.config({
    path: path.resolve(process.cwd(), "day-1-setup/.env"),
});

// Fallback to port 3000 if not defined
export const PORT: number = parseInt(process.env.PORT || "3000", 10);

6/9 server.ts

day-1-setup/src/server.ts
import express from "express";
import { PORT } from "@/config/environment";

const app = express();

// Middleware: Parse JSON request bodies
app.use(express.json());

// Health check route
app.get("/api/v1/health", (request, response) => {
    response.status(200);
    response.json({
        status: "ok",
    });
});

// Start server on configured port
app.listen(PORT, () => {
    console.log(`🚀 server running on http://localhost:${PORT}`);
});
