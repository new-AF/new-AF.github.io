Binary Search Trees In TypeScript

Overview

Binary Search Trees (BSTs) are Binary Trees, with an additional constraint, where for each node:

  • all values in the left subtree are smaller (than the node value), and

  • all values in the right subtree are bigger (than the node value).

This additional constraint makes

Let's unpack that.

Binary Tree

A Tree is a data structure made of nodes connected in a specific way:

  1. One Node is the root node

  2. Each node can have 0, 1, or nchildren nodes

  3. Each node except for the root node, has exactly one parent

A Binary Tree is just a tree where each node has at most two children (0, 1 or 2).

This additional rule makes a BST efficient when performing search on its elements.

But there is a caveat:

To be specific, for a typical BST implementation that supports these operations:

  • Insertion.

  • Deletion.

  • Searching.

Each of these operations run in O(n) for the single element, and O(n²) for n elements, which is slow compared to equivalent data structures.

Likewise, sorting is also O(n²). This is because you have to insert n elements beforehand at a total cost of O(n²), and later obtain the sorted collection in O(n).

Because of the bad guarantee in the worst case, plain BSTs are rarely used in real-world applications, however the underlying concepts and algorithms are foundational for building improved versions (AVL and Red-Black trees) that do offer efficient O(log n) for the single operation and O(n log n) for n elements.

Tree types

The type of the tree depends on how many children each node has:

  • Binary Trees, each node has two children

Another side benefit of BSTs is you implement a sorting algorithm without directly writing a sorting algorithm, we'll see that later.

A TypeScript implementation

To focus on the algorithms part without getting bogged down by Class-based boilerplate, I implemented the solution using a Functional programming approach:

  • Plain Objects that represent Node and BST

  • Pure functions that accept the Object, manipulate its content, and return it back.

Tree construction algorithm

2    // create empty bst

The construction algorithm is simple: we create an empty BST (with root null), and repeatedly inserting the elements into it. insertIntoBst does all the heavy-lifting here.

The Constructor Algorithm

It accepts and converts (an array of) data into a BST with the following algorithm:

  • Set the root node witht the first element,

  • repeatedly call insert for each subsequent element.

The Insert Algorithm 🔑

JavaScript
1insertValue(val) {
2    const newNode = new Node(val);
3
4    if (this.isRootUnset()) {
5        this.setRootNode(newNode);
6        return;
7    }
8
9    /* recursive 'helper' insert */
10    const recursiveFunction = (currentNode, val) => {
11        if (isUndefinedOrNull(currentNode)) return;
12
13        /* if value <  current node, and there is an has an empty left spot then set new node, otherwise unpack */
14        if (val < currentNode.value()) {
15            if (currentNode.hasEmptyLeftSpot()) {
16                currentNode.setLeftNode(newNode);
17                return;
18            }
19            recursiveFunction(currentNode.leftNode(), val);
20        }
21
22        /* if value <  current node, and there is an has an empty left spot then set new node, otherwise unpack */
23        if (val > currentNode.value()) {
24            if (currentNode.hasEmptyRightSpot()) {
25                currentNode.setRightNode(newNode);
26                return;
27            }
28            recursiveFunction(currentNode.rightNode(), val);
29        }
30
31        /* end of recursive function */
32    };
33
34    /* start recursively from _root node */
35    recursiveFunction(this.root(), val);
36}

insert is effectively the bacbkone of constructing the Binary Search Tree in memory. The algorithm is the following:

  1. Start from the root node

  2. check if the root node has been set, if not then set it,

  3. if the root node is set, check if the value-to-be-inserted is lower then root node,

  4. if value-to-be-inserted is lower then root node, we know the value will be inserted somewhere in the left subtree

  5. check if the left spot is empty

  6. if the left spot is empty, set the new node there

  7. if the left spot is not empty, start recursively from Step 4.

The same steps are to be followed if the value-to-be-inserted is greater than the current node:

  1. check if the right spot is empty,

  2. if yes, set the new node there,

  3. if not recursively start from that right node, and go left or right based on comparing the value inside

The Preorder Traversal Algorithm 🔑

Node.js module (mjs)
1/* fileName: BinarySearchTree.mjs */
2
3traversePreOrder() {
4    /* recursive traversal */
5    const recursiveFunction = (currentNode, array) => {
6        /* ends recursion when it reaches either end of left or right tree */
7        if (isUndefinedOrNull(currentNode)) return;
8
9        /* visit root */
10        array.push(currentNode.value());
11
12        recursiveFunction(currentNode.leftNode(), array);
13
14        recursiveFunction(currentNode.rightNode(), array);
15
16        return array;
17    };
18
19    return recursiveFunction(this.root(), []);
20}

Traversal is an an algorithm, a systematic way of visiting every node in the tree.

That is if you were given the root reference of a tree, how would you write an algorithm to visit each node.

There are 3 base traversal methods:

  1. Preorder

  2. Inorder

  3. Postorder

Strictly you don't have return anything from the traversal method, as simply visiting each node will suffice. However for my traversal methods I chose to return all elements I traversed in an array.

For Preorder the following recursive algorithm is used:

  1. Visit the node

  2. Visit the left subtree

  3. Visit the right subtree
