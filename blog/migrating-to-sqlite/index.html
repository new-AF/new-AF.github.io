Migrating to SQLite

Abdullah Fatota
Updated: 30 May 2026

Overview

SQL (Structured Query Language) is a declarative programming language that powers both open-source and commercial databases. Declarative means you don't write the algorithm like with JavaScript, but instead describe what you want, and the SQL engine determines the best execution plan and delivers the result.

We'll use SQLite which uses local files as databases without the need to install external programs.

Initially we'll write raw SQL commands to migrate our controllers from our in-memory array of objects storage to a fully-fledged local SQL database. However, later we'll improve DX by using an ORM (Object-relational mapping) to manipulate the database using objects and methods, much like JavaScript constructs.

Objectives

  • Install better-sqlite3 to gain SQL support and manage our local database.

  • Gradually migrate our src/controllers to SQLite, by utilizing our test cases to fix any bugs during the process.

SQL Definitions

Database

A Database is a collection of Tables.

In SQLite each Database is a single file, often with extension .db

Tables

SQL stores data in Tables, which have conceptual Rows and Columns. Example users table:

Unknown Code
1users
2┌────┬───────┬─────────────────────┐
3│ id │ name  │ email               │
4├────┼───────┼─────────────────────┤
5│  1 │ Alice │ alice@example.com   │
6│  2 │ Bob   │ bob@example.com     │
7└────┴───────┴─────────────────────┘

In a table we have:

  • A Row which is a grouping of cells/data/user information to be inserted into or retrieved from the table.

  • A Column which specifies the names, data type and constraints of all cells in that single column.

Examples of Column Data types include:

  • INTEGER for storing whole numbers (e.g. column id)

  • TEXT for storing strings of text (e.g. columns name, email)

Note that NULL is an acceptable cell value in those columns unless constrained.

Constraints

Constraints are additional rules on the data type of that column/cell:

  • NOT NULL means the no NULL cell values.

  • UNIQUE means no duplicate values across the column, suitable for email, national ID, license plates data.

  • PRIMARY KEY is often an unique INTEGER that uniquely identifies that Row in the entire table.

When we insert rows into the table, each cell must adhere to that column's data type and constraints.

Schema

Schema is the umbrella term for all column names, their data type and constraints. They specify the data structure of tha table.

The SQL is

Unknown Code
1CREATE TABLE users (
2    id INTEGER PRIMARY KEY AUTOINCREMENT,
3    name TEXT NOT NULL,
4    email TEXT NOT NULL UNIQUE
5);

We creating table users with 3 columns:

  • id stores unique INTEGERs (from 1 upwards) which SQLite automatically increments for us, so no need to provide this cell value when we insert data/rows later.

  • name stores strings of text, it can still be the empty string (""), because the constraint NOT NULL only means no literal NULL values.

  • email stores strings that must be unique across the entire column because of the UNIQUE applied constraint, also doesn't accept NULL values.

seedUsers.ts migrates our saved users from our in-memory storage to the new SQL users table:

TypeScript
1[
2    { id: 1, name: "Alice", email: "alice@example.com" },
3    { id: 2, name: "Bob", email: "bob@example.com" },
4];
TypeScript
1/* fileName: src/database/seedUsers.ts */
2import { type Database } from "better-sqlite3";
3import { users as allUsers } from "@/data/users.store";
4
5export const seedUsers = (database: Database) => {
6    const statement = database.prepare(
7        `INSERT INTO users (name, email) VALUES (?, ?)`
8    );
9    for (const { name, email } of allUsers) {
10        statement.run(name, email);
11    }
12};

The SQL is

Unknown Code
1INSERT INTO users (name, email) VALUES (?, ?)

This is called a prepared SQL statement because of the placeholders (sql: ?), and it protects against injection attacks which could delete our entire database. This is because name and email are external variables and may contain malicious instructions if insert them directly. So the SQL-engine safely sanitizes name and email and creates this SQL statement:

Unknown Code
1INSERT INTO users (name, email) VALUES ('Alice', 'alice@example.com')
2INSERT INTO users (name, email) VALUES ('Bob', 'bob@example.com')

We didn't provide id value because SQLite does that automatically (it starts with 1 then upward).

INSERT will throw an error SqliteError: UNIQUE constraint failed: users.email if the email address already exists in the column, this is because UNIQUE constraint has been set on the email column and SQLite is enforcing it.

getUser (GET)

ts: getUser handling GET /api/v1/users/:id refines the sql: SELECT * statement by adding the WHERE clause. WHERE filters the rows to only return those matching a specific condition, in this matching the id from the HTTP request.

Because column id has constraint PRIMARY KEY it's guaranteed to be unique, so the whole SQL statement returns at most 1 row.

Here's our updated SQL-powered controller:

4import { database } from "@/database/connection";

6

8    // Search users 'database', returns first matching object, or `undefined` if none are found
9    // SQL: check if `id` exists in db

11        "SELECT * FROM users WHERE id = ?"
12    );
13    // `undefined` or {id : 1, ...}
14    const searchUserResult = searchUserStatement.get(userId);
15

17        // id does not exists in db

19    }

createUser (POST)

Because sql: INSERT throws an error if the email already exists in the table we have to update our controller to reflect this change:

  • we'll return error code 409 (conflict) if we receive a payload with duplicate email.

  • otherwise we insert the data (name & email) into the table.

The main SQL is

Unknown Code
1INSERT INTO users (name, email) VALUES (?, ?);

This a prepared statement where better-sqlite3 will replace placeholders with name and email from POST payload.

We'll also need to check if email already exists in table:

Unknown Code
1SELECT 1 FROM users WHERE email = ? LIMIT 1

After we bind the email, this statement returns 1 in the column (named 1 as well) if the email exists, or undefined if it's a new email.

Finally, we'll need to find how many rows i.e. users are in the table in order to generate the id

Unknown Code
1SELECT COUNT(*) as count FROM users;

COUNT(*) will return the number of rows in column named count as well, that we'll extract later.

Here's our updated SQL-powered controller:

TypeScript
1/* fileName: src/controllers/createUser.ts */
2import { Request, Response } from "express";
3import { z } from "zod";
4import { database } from "@/database/connection";
5import { userModelSchema, type UserModel } from "@/validators/users/user.model";
6import { createUserSchema } from "@/validators/users/user.requests";
7
8// POST /users
9export const createUser = (request: Request, response: Response) => {
10    // Request body already parsed as JSON
11    const requestBody = request.body;
12
13    const bodyResult = createUserSchema.safeParse(requestBody);
14    const { success, data, error } = bodyResult;
15
16    if (success === false) {
17        // Bad request, often malformed user input
18        response.status(400);
19        response.json({
20            error: z.flattenError(error),
21        });
22        return;
23    }
24
25    // Payload name, email
26    const { name, email } = data;
27
28    // SQL: check if email exists in db
29    const emailFoundStatement = database.prepare(
30        "SELECT 1 FROM users WHERE email = ? LIMIT 1"
31    );
32    // `undefined` or {'1' : 1}
33    const emailFound = emailFoundStatement.get(email);
34
35    if (typeof emailFound === "object" && "1" in emailFound) {
36        // conflict, email already exists in db
37        response.status(409);
38        response.json({
39            message: `email already exists in database. Use PATCH to update user details`,
40        });
41        return;
42    }
43
44    // SQL: find how many rows in database
45    const countStatement = database.prepare(
46        "SELECT COUNT(*) as count FROM users;"
47    );
48    const row = countStatement.get();
49    const count = row.count;
50    const newUser: UserModel = { id: count + 1, name, email };
51
52    // Validate final model shape as a guard-rail
53    const modelCheck = userModelSchema.safeParse(newUser);
54    if (modelCheck.success === false) {
55        response.status(500);
56        response.json({ error: "Internal model validation failed." });
57        return;
58    }
59
60    // SQL: Insert into database
61    const statement = database.prepare(`
62        INSERT INTO users (name, email) VALUES (?, ?);    
63    `);
64    statement.run(name, email);
65
66    // Resource created
67    response.status(201);
68    response.json(newUser);
69};

updateUser (PATCH)

Because PATCH will provide us with at least either name or email we have to dynamically construct the UPDATE SQL query:

Unknown Code
1UPDATE users SET name = ?, email = ? WHERE id = ?

This is because if we provide either as undefined SQLite will attempt to set cell as NULL, which will raise an SQLiteError because of the NOT NULL constraint on either columns.

Instead we'll join the name = ? and email = ? fields:

TypeScript
1// SQL: construct UPDATE statement
2const fields = [];
3const fieldValues = [];
4if (name !== undefined) {
5    fields.push("name = ?");
6    fieldValues.push(name);
7}
8if (email !== undefined) {
9    fields.push("email = ?");
10    fieldValues.push(email);
11}
12fieldValues.push(id);
13
14// name = ?, email = ? (if both are provided)
15const fieldsPart = fields.join(", ");
16const statement = database.prepare(
17    `UPDATE users SET ${fieldsPart} WHERE id = ?`
18);
19statement.run(...fieldValues);

deleteUser (DELETE)

deleteUser will use the sql: DELETE to remove the user entry from the table. It uses the WHERE clause to match the row to remove.

Here's our updated SQL-powered controller:

TypeScript
1/* fileName: src/controllers/deleteUser.ts */
2import { NextFunction, Request, Response } from "express";
3import { database } from "@/database/connection.ts";
4import { userIdParamsSchema } from "@/validators/users/user.params";
5
6const deleteUserCore = (request: Request, response: Response) => {
7    const { params } = request;
8    const paramsResult = userIdParamsSchema.safeParse(params);
9
10    if (paramsResult.success === false) {
11        // Zod Error, handled by `errorHandler` middleware
12        throw paramsResult.error;
13    }
14
15    const id = paramsResult.data.id;
16
17    // SQL: check if `id` exists in db
18    const searchUserStatement = database.prepare(
19        "SELECT 1 FROM users WHERE id = ? LIMIT 1"
20    );
21    // `undefined` or {'1' : 1}
22    const searchUserResult = searchUserStatement.get(id);
23
24    if (searchUserResult === undefined) {
25        // id does not exists in db
26        response.status(404);
27        response.json({
28            message: `User with id ${id} not found`,
29        });
30        return;
31    }
32
33    // Delete user
34    const statement = database.prepare(`DELETE FROM users WHERE id = ?`);
35    const result = statement.run(id);
36
37    // Confirm user deleted
38    // {changes: 1 // confirms how many rows were deleted }
39    if (result.changes !== 1) {
40        response.status(500);
41        response.json({
42            message: "user not deleted, internal database error",
43        });
44    }
45
46    // Success, no content
47    response.status(204);
48    response.send();
49};

51export const deleteUser = (
52    request: Request,
53    response: Response,
54    next: NextFunction
55) => {
56    try {
57        deleteUserCore(request, response);
58    } catch (error) {
59        // Call error handler middleware
60        next(error);
61    }
62};

Unknown Code
1DELETE FROM users WHERE id = ?

It's a standard prepared statement, where we provide the id of the row to remove.
