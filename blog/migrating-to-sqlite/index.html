Migrating to SQLite

By: Abdullah Fatota
Last updated: 31 March 2026

SQL (Structured Query Language) is a declarative programming language that powers both open-source and commercial databases. Declarative means you don't write the algorithm like with JavaScript, but instead describe what you want, and the SQL engine determines the best execution plan and delivers the result.

We'll use SQLite which uses local files as databases without the need to install external programs.

Initially we'll write raw SQL commands to migrate our controllers from our in-memory array of objects storage to a fully-fledged local SQL database. However, later we'll improve DX by using an ORM (Object-relational mapping) to manipulate the database using objects and methods, much like JavaScript constructs.

Objectives

  • Install better-sqlite3 to gain SQL support and manage our local database.
  • Gradually migrate our src/controllers to SQLite, by utilizing our test cases to fix any bugs during the process.

SQL Definitions

Database

A Database is a collection of Tables.

In SQLite each Database is a single file, often with extension .db

Tables

SQL stores data in Tables, which have conceptual Rows and Columns. Example users table:

users
┌────┬───────┬─────────────────────┐
│ id │ name  │ email               │
├────┼───────┼─────────────────────┤
│  1 │ Alice │ alice@example.com   │
│  2 │ Bob   │ bob@example.com     │
└────┴───────┴─────────────────────┘

In a table we have:

  • A Row which is a grouping of cells/data/user information to be inserted into or retrieved from the table.
  • A Column which specifies the names, data type and constraints of all cells in that single column.

Examples of Column Data types include:

  • INTEGER for storing whole numbers (e.g. column id)
  • TEXT for storing strings of text (e.g. columns name, email)

Note that NULL is an acceptable cell value in those columns unless constrained.

Constraints

Constraints are additional rules on the data type of that column/cell:

  • NOT NULL means the no NULL cell values.
  • UNIQUE means no duplicate values across the column, suitable for email, national ID, license plates data.
  • PRIMARY KEY is often an unique INTEGER that uniquely identifies that Row in the entire table.

When we insert rows into the table, each cell must adhere to that column's data type and constraints.

Schema

Schema is the umbrella term for all column names, their data type and constraints. They specify the data structure of tha table.

dropTable.ts deletes our users table allowing us to start anew, we need this for our tests and ongoing lessons. But in production this is a dangerous command because it deletes everything.

src/database/dropTable.ts
import { database } from "./connection";

export const dropTable = () => {
    const statement = database.prepare("DROP TABLE IF EXISTS users;");
    statement.run();
};

createSchema.ts creates our users table and its schema (column names, their data types and any constraints).

src/database/createSchema.ts
import { type Database } from "better-sqlite3";

export const createSchema = (database: Database) => {
    const sql = `
        CREATE TABLE users (
            id INTEGER PRIMARY KEY AUTOINCREMENT,
            name TEXT NOT NULL,
            email TEXT NOT NULL UNIQUE
        );
    `;
    database.exec(sql);
};

The SQL is

sql
CREATE TABLE users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    email TEXT NOT NULL UNIQUE
);

We creating table users with 3 columns:

  • id stores unique INTEGERs (from 1 upwards) which SQLite automatically increments for us, so no need to provide this cell value when we insert data/rows later.

  • name stores strings of text, it can still be the empty string (""), because the constraint NOT NULL only means no literal NULL values.

  • email stores strings that must be unique across the entire column because of the UNIQUE applied constraint, also doesn't accept NULL values.

seedUsers.ts migrates our saved users from our in-memory storage to the new SQL users table:

ts
[
    { id: 1, name: "Alice", email: "alice@example.com" },
    { id: 2, name: "Bob", email: "bob@example.com" },
];

src/database/seedUsers.ts
import { type Database } from "better-sqlite3";
import { users as allUsers } from "@/data/users.store";

export const seedUsers = (database: Database) => {
    const statement = database.prepare(
        `INSERT INTO users (name, email) VALUES (?, ?)`
    );
    for (const { name, email } of allUsers) {
        statement.run(name, email);
    }
};

The SQL is

sql
INSERT INTO users (name, email) VALUES (?, ?)

This is called a prepared SQL statement because of the placeholders (sql: ?), and it protects against injection attacks which could delete our entire database. This is because name and email are external variables and may contain malicious instructions if insert them directly. So the SQL-engine safely sanitizes name and email and creates this SQL statement:

sql
INSERT INTO users (name, email) VALUES ('Alice', 'alice@example.com')
INSERT INTO users (name, email) VALUES ('Bob', 'bob@example.com')

We didn't provide id value because SQLite does that automatically (it starts with 1 then upward).

INSERT will throw an error SqliteError: UNIQUE constraint failed: users.email if the email address already exists in the column, this is because UNIQUE constraint has been set on the email column and SQLite is enforcing it.

getUser (GET)

ts: getUser handling GET /api/v1/users/:id refines the sql: SELECT * statement by adding the WHERE clause. WHERE filters the rows to only return those matching a specific condition, in this matching the id from the HTTP request.

Because column id has constraint PRIMARY KEY it's guaranteed to be unique, so the whole SQL statement returns at most 1 row.

Here's our updated SQL-powered controller:

src/controllers/getUser.ts
import { Request, Response } from "express";
import { z } from "zod";
import { database } from "@/database/connection";
import { userIdParamsSchema } from "@/validators/users/user.params";

export const searchUsers = (userId: Number) => {
    // Search users 'database', returns first matching object, or `undefined` if none are found
    // SQL: check if `id` exists in db
    const searchUserStatement = database.prepare(
        "SELECT * FROM users WHERE id = ?"
    );
    // `undefined` or {id : 1, ...}
    const searchUserResult = searchUserStatement.get(userId);

    if (searchUserResult === undefined) {
        // id does not exists in db
        return { success: false };
    }

    return { success: true, user: searchUserResult };
};

// GET /users/:id
export const getUser = (request: Request, response: Response) => {
    const {
        success: paramParseSuccess,
        data,
        error,
    } = userIdParamsSchema.safeParse(request.params);

    if (paramParseSuccess === false) {
        response.status(400);
        response.json({ error: z.flattenError(error) });
        return;
    }

    const { id: userId } = data;

    const { success, user } = searchUsers(userId);
    if (!success) {
        response.status(404);
        response.json({
            message: `User with id ${userId} not found`,
        });
        return;
    }

    response.status(200);
    response.json(user);
};

The raw SQL is

sql
SELECT * FROM users WHERE id = ? LIMIT 1

createUser (POST)

Because sql: INSERT throws an error if the email already exists in the table we have to update our controller to reflect this change:

  • we'll return error code 409 (conflict) if we receive a payload with duplicate email.
  • otherwise we insert the data (name & email) into the table.

The main SQL is

sql
INSERT INTO users (name, email) VALUES (?, ?);

This a prepared statement where better-sqlite3 will replace placeholders with name and email from POST payload.

We'll also need to check if email already exists in table:

sql
SELECT 1 FROM users WHERE email = ? LIMIT 1

After we bind the email, this statement returns 1 in the column (named 1 as well) if the email exists, or undefined if it's a new email.

Finally, we'll need to find how many rows i.e. users are in the table in order to generate the id

sql
SELECT COUNT(*) as count FROM users;

COUNT(*) will return the number of rows in column named count as well, that we'll extract later.

Here's our updated SQL-powered controller:

src/controllers/createUser.ts
import { Request, Response } from "express";
import { z } from "zod";
import { database } from "@/database/connection";
import { userModelSchema, type UserModel } from "@/validators/users/user.model";
import { createUserSchema } from "@/validators/users/user.requests";

// POST /users
export const createUser = (request: Request, response: Response) => {
    // Request body already parsed as JSON
    const requestBody = request.body;

    const bodyResult = createUserSchema.safeParse(requestBody);
    const { success, data, error } = bodyResult;

    if (success === false) {
        // Bad request, often malformed user input
        response.status(400);
        response.json({
            error: z.flattenError(error),
        });
        return;
    }

    // Payload name, email
    const { name, email } = data;

    // SQL: check if email exists in db
    const emailFoundStatement = database.prepare(
        "SELECT 1 FROM users WHERE email = ? LIMIT 1"
    );
    // `undefined` or {'1' : 1}
    const emailFound = emailFoundStatement.get(email);

    if (typeof emailFound === "object" && "1" in emailFound) {
        // conflict, email already exists in db
        response.status(409);
        response.json({
            message: `email already exists in database. Use PATCH to update user details`,
        });
        return;
    }

    // SQL: find how many rows in database
    const countStatement = database.prepare(
        "SELECT COUNT(*) as count FROM users;"
    );
    const row = countStatement.get();
    const count = row.count;
    const newUser: UserModel = { id: count + 1, name, email };

    // Validate final model shape as a guard-rail
    const modelCheck = userModelSchema.safeParse(newUser);
    if (modelCheck.success === false) {
        response.status(500);
        response.json({ error: "Internal model validation failed." });
        return;
    }

    // SQL: Insert into database
    const statement = database.prepare(`
        INSERT INTO users (name, email) VALUES (?, ?);    
    `);
    statement.run(name, email);

    // Resource created
    response.status(201);
    response.json(newUser);
};

updateUser (PATCH)

Because PATCH will provide us with at least either name or email we have to dynamically construct the UPDATE SQL query:

sql
UPDATE users SET name = ?, email = ? WHERE id = ?

This is because if we provide either as undefined SQLite will attempt to set cell as NULL, which will raise an SQLiteError because of the NOT NULL constraint on either columns.

Instead we'll join the name = ? and email = ? fields:

ts
// SQL: construct UPDATE statement
const fields = [];
const fieldValues = [];
if (name !== undefined) {
    fields.push("name = ?");
    fieldValues.push(name);
}
if (email !== undefined) {
    fields.push("email = ?");
    fieldValues.push(email);
}
fieldValues.push(id);

// name = ?, email = ? (if both are provided)
const fieldsPart = fields.join(", ");
const statement = database.prepare(
    `UPDATE users SET ${fieldsPart} WHERE id = ?`
);
statement.run(...fieldValues);

And we'll also the SELECT 1 pattern to check if user with id exists in table.

sql
SELECT 1 FROM users WHERE id = ? LIMIT 1

Finally once we update the user we'll retrieve and echo it as part 200 response.

sql
`SELECT * FROM users WHERE id = ?`

Here's our updated SQL-powered controller:

src/controllers/updateUser.ts
import { Request, Response } from "express";

import { userModelSchema, type UserModel } from "@/validators/users/user.model";
import { userIdParamsSchema } from "@/validators/users/user.params";
import { patchUserSchema } from "@/validators/users/user.requests";

const formatErrors = (error: z.ZodError) => z.flattenError(error);

export const updateUser = (request: Request, response: Response) => {
    // Validate id param
    const paramsResult = userIdParamsSchema.safeParse(request.params);
    if (paramsResult.success === false) {
        response.status(400);
        response.json({ errors: formatErrors(paramsResult.error) });
        return;
    }

    // Validate payload, either `name` or `email` must be provided, and in format we expect
    const bodyResult = patchUserSchema.safeParse(request.body);
    if (bodyResult.success === false) {
        // Bad request
        response.status(400);
        response.json({ errors: formatErrors(bodyResult.error) });
        return;
    }

    // extract Param
    const { id } = request.params;
    // extract Payload
    const { name, email } = request.body;

    // Search user
    // SQL: check if `id` exists in db
    const searchUserStatement = database.prepare(
        "SELECT 1 FROM users WHERE id = ? LIMIT 1"
    );
    // `undefined` or {'1' : 1}
    const searchUserResult = searchUserStatement.get(id);

    if (searchUserResult === undefined) {
        // id does not exists in db
        response.status(404);
        response.json({
            message: `User with id ${id} not found`,
        });
        return;
    }

    // SQL: construct UPDATE statement
    const fields = [];
    const fieldValues = [];
    if (name !== undefined) {
        fields.push("name = ?");
        fieldValues.push(name);
    }
    if (email !== undefined) {
        fields.push("email = ?");
        fieldValues.push(email);
    }
    fieldValues.push(id);

    // name = ?, email = ? (if both are provided)
    const fieldsPart = fields.join(", ");
    const statement = database.prepare(
        `UPDATE users SET ${fieldsPart} WHERE id = ?`
    );
    statement.run(...fieldValues);

    // SQL: retrieve new user
    const getStatement = database.prepare(`SELECT * FROM users WHERE id = ?`);
    const updatedUser = getStatement.get(id);

    console.log({ updatedUser });

    response.status(200);
    response.json(updatedUser);
};

replaceUser (PUT)

The logic here is similar to PATCH and it's easier because we don't have to construct the fields for sql: UPDATE because we know we'll be getting both name and email as this part of Payload schema validation.

We'll still use the SELECT 1 pattern to check if user with id exists in table.

sql
SELECT 1 FROM users WHERE id = ? LIMIT 1

And the sql: UPDATE statement to replace user's details:

sql
UPDATE users SET name = ?, email = ? WHERE id = ?

Finally we'll echo back the existing user with updated details:

sql
SELECT * FROM users WHERE id = ?

Here's our updated SQL-powered controller:

src/controllers/replaceUser.ts
import { Request, Response } from "express";
import { email, z } from "zod";
import { database } from "@/database/connection";
import { userIdParamsSchema } from "@/validators/users/user.params";
import { userModelSchema, type UserModel } from "@/validators/users/user.model";
import { putUserSchema } from "@/validators/users/user.requests";

export const replaceUser = (request: Request, response: Response) => {
    const { params, body } = request;

    // Validate id param
    const {
        success: userIdParamSuccess,
        data: userIdParamData,
        error: userIdParamError,
    } = userIdParamsSchema.safeParse(params);

    if (userIdParamSuccess === false) {
        // Bad request
        response.status(400);
        response.json({
            error: z.flattenError(userIdParamError),
        });
        return;
    }

    // extract `id`
    const { id } = params;

    // Search user
    // SQL: check if `id` exists in db
    const searchUserStatement = database.prepare(
        "SELECT 1 FROM users WHERE id = ? LIMIT 1"
    );
    // `undefined` or {'1' : 1}
    const searchUserResult = searchUserStatement.get(id);

    if (searchUserResult === undefined) {
        // id does not exists in db
        response.status(404);
        response.json({
            message: `User with id ${id} not found`,
        });
        return;
    }

    // Validate payload
    const {
        success: bodySuccess,
        error: bodyError,
        data: putPayload,
    } = putUserSchema.safeParse(body);

    if (bodySuccess === false) {
        response.status(400);
        response.json({
            error: z.flattenError(bodyError),
        });
        return;
    }

    // Extract name, email
    const { name, email } = body;

    // SQL: Update user
    const statement = database.prepare(
        `UPDATE users SET name = ?, email = ? WHERE id = ?`
    );
    statement.run(name, email, id);

    // SQL: retrieve new user
    const getStatement = database.prepare(`SELECT * FROM users WHERE id = ?`);
    const updatedUser = getStatement.get(id);

    // console.log({ updatedUser });

    // Echo user back
    response.status(200);
    response.json(updatedUser);

deleteUser (DELETE)

deleteUser will use the sql: DELETE to remove the user entry from the table. It uses the WHERE clause to match the row to remove.

Here's our updated SQL-powered controller:

src/controllers/deleteUser.ts
import { NextFunction, Request, Response } from "express";
import { database } from "@/database/connection.ts";
import { userIdParamsSchema } from "@/validators/users/user.params";

const deleteUserCore = (request: Request, response: Response) => {
    const { params } = request;
    const paramsResult = userIdParamsSchema.safeParse(params);

    if (paramsResult.success === false) {
        // Zod Error, handled by `errorHandler` middleware
        throw paramsResult.error;
    }

    const id = paramsResult.data.id;

    // SQL: check if `id` exists in db
    const searchUserStatement = database.prepare(
        "SELECT 1 FROM users WHERE id = ? LIMIT 1"
    );
    // `undefined` or {'1' : 1}
    const searchUserResult = searchUserStatement.get(id);

    if (searchUserResult === undefined) {
        // id does not exists in db
        response.status(404);
        response.json({
            message: `User with id ${id} not found`,
        });
        return;
    }

    // Delete user
    const statement = database.prepare(`DELETE FROM users WHERE id = ?`);
    const result = statement.run(id);

    // Confirm user deleted
    // {changes: 1 // confirms how many rows were deleted }
    if (result.changes !== 1) {
        response.status(500);
        response.json({
            message: "user not deleted, internal database error",
        });
    }

    // Success, no content
    response.status(204);
    response.send();
};

export const deleteUser = (
    request: Request,
    response: Response,
    next: NextFunction
) => {
    try {
        deleteUserCore(request, response);
    } catch (error) {
        // Call error handler middleware
        next(error);
    }
};

The main SQL statement is:

sql
DELETE FROM users WHERE id = ?

It's a standard prepared statement, where we provide the id of the row to remove. To confirm the operation was successful, SQLite returns key changes representing number of deleted rows, in this case it should be 1, anything other than that means something wrong has happened, so we return error code 500 and a helpful message.
